# Architecture Overview & Critical Review
**Based on the `main` branch Final Documentation (c1v7x2nsmdfr2)**

---

## 1. Architecture Overview

The current pipeline is a highly sophisticated, multi-stage hybrid system designed specifically to optimize the Expected F0.5 metric under a strict one-owner constraint.

### A. Candidate Generation (Blocking)
- **Methodology:** Country-scoped, multi-key inverted index (sparse blocking).
- **Keys Used (9 passes):** Uses combinations of address numbers, address words, name bigrams, phonetic tokens, and space-free names (`_k7` candidate set). 
- **Sibling Propagation:** Empty-address records inherit candidates from same-country/core-name peers.
- **Recall:** Achieves **97.61%** recall, acting as a hard upper bound (~0.99 oracle F0.5) for the downstream models.

### B. Pair Classifier (Stage 1 & 2 GBDT)
- **Normalisation:** Heavy rule-based preprocessing (accent folding, leetspeak decoding, address canonicalization) and a learned 1,312-word Indic-to-Latin phonetic dictionary.
- **Stage 1 (Base):** XGBoost model evaluating ~91 standard features (RapidFuzz string similarities, token overlap, IDF weights, exact/truncated number matches).
- **Stage 2 (Context-Aware):** A second XGBoost model that uses 3-fold cross-fitting (consistent stacking). It sees:
  - **Competition Context:** The score of the best competing S1 entity for the same record.
  - **Generator Record-Cluster Features:** 12 features that model sibling support (e.g., whether a record's typo or house number is corroborated by other S2/S3 candidates of the same S1).

### C. Cross-Encoders (Stage 3)
- **Targeted Application:** Applied *only* to the ~1% "uncertain band" (where Stage 2 probability is between 0.02 and 0.98).
- **Models:** Fine-tuned `xlm-roberta-base` and `mDeBERTa-v3-base`.
- **Band Combiner (Stage 3 XGB):** Blends the GBDT probabilities with cross-encoder logits, injecting three new structural priors:
  1. **Sibling Similarity:** How similar the record is to other records the S1 already confidently accepts.
  2. **Raw-Text Namesakes:** Margin and rank against all other competing S1 entities on *un-normalized* text.
  3. **Record "Owner" Prior:** A character n-gram SGD model predicting if the record is a decoy.

### D. Structured Decoding
- **Methodology:** Exact Poisson-binomial dynamic programming.
- **Logic:** Assigns each record to its single highest-scoring S1 (one-owner constraint), then per S1, picks the top-$k$ candidates that mathematically maximize the Expected F0.5.

### E. Unseen Country Strategy (France)
- **Adaptation:** Since France has no train labels, the pipeline relies on transductive pseudo-labeling. 
- **Execution:** Uses confident predictions from the US/India model to fine-tune the mDeBERTa cross-encoder specifically on French test pairs (Round 2 adaptation).

## 2. Potential Flaws and Architectural Vulnerabilities

While highly engineered and performant (Public LB ~0.984), the architecture contains structural vulnerabilities against the specific demands of the Amazon ML challenge.

### Vulnerability 1: The Sparse Blocking Ceiling
- **The Flaw:** Blocking relies entirely on exact token/n-gram/number overlaps. It caps true recall at **97.61%**, mathematically preventing the F0.5 score from ever crossing ~0.99.
- **The Issue:** It fails on ~146k records that have empty addresses and highly common names, or names that have been entirely swapped for unrelated coined words. The pipeline's attempt to use "one-hop sibling retrieval" failed (99.9% false positives).
- **Blind Spot:** Without a dense semantic dual-encoder (e.g., FAISS + bi-encoder) at the blocking stage, entities with severe typos or transliteration collapse will never reach the classifier.

### Vulnerability 2: Transductive Amplification of Bias (France)
- **The Flaw:** France adaptation relies heavily on pseudo-labels generated by a model trained solely on US/India data.
- **The Issue:** As noted in the documentation, French addresses structurally differ (département vs. région, shorter house numbers). If the US-trained Stage 2 model is systematically confused by French départements, it will generate confident *false* pseudo-labels. Fine-tuning mDeBERTa on these poisoned pseudo-labels will permanently bake the bias into the final predictions. 

### Vulnerability 3: The "Certainty Trap" (Cross-Encoder Band Limit)
- **The Flaw:** Cross-encoders are strictly gated to pairs where $0.02 < p_{GBDT} < 0.98$.
- **The Issue:** F0.5 heavily punishes false positives (precision is weighted 2x). If the Stage 2 GBDT is confidently wrong about a cleverly constructed sister-business decoy ($p = 0.99$), the cross-encoder *never sees it* and cannot correct it. This over-reliance on the GBDT's calibration leaves the pipeline vulnerable to adversarial decoys.

### Vulnerability 4: Brittle Feature Engineering vs. Representation Learning
- **The Flaw:** The pipeline uses ~91 hand-crafted string features and heavily hardcoded normalization rules (e.g., dropping specific prefixes, hardcoded French abbreviations).
- **The Issue:** As the data generator evolves (or in the hidden test split), new abbreviations or noise patterns will bypass the regex rules. The cross-encoders could handle this naturally, but because they are relegated to a tiny 1% band, the brittle manual features dictate 99% of the decisions. 

### Vulnerability 5: Overfitting the "Record Prior"
- **The Flaw:** The Stage-3 model uses a character n-gram SGD classifier to predict if a record is a decoy, independent of any S1.
- **The Issue:** Decoys in the test set (which has 2x the decoy density) might be generated from a different distribution or dictionary than train decoys. A character n-gram model is highly susceptible to overfitting to the specific synthetic text patterns of the train split decoys, rather than learning true generalizable rules.

### Summary
The current architecture is a **masterclass in exploiting the specific synthetic data generation mechanics** of the training set (e.g., exploiting sibling clusters and exact probability margins). However, it is fundamentally **rigid**. It trades semantic understanding for hardcoded rules and strict gating mechanisms, leaving it vulnerable to out-of-distribution shifts (like France) and hard-capped by its sparse blocking limitations.
